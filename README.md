# Библиотека: вход, роли и защита маршрутов

Практическая работа 5. К приложению из практической работы 4 добавлены регистрация и вход, три роли с разными возможностями, защита маршрутов, обновление токена и управление временем жизни сессии.

## Запуск

1. Сервер. Лекционный `mock-server.js` не изменён. Для этой работы рядом лежит его копия с добавками (`tools/mock-server-pr5.js`, добавки помечены комментарием «ПР5»):

       node tools/mock-server-pr5.js --port 8080 --origin http://localhost:5555

   Чтобы проверить обновление токена, срок его жизни сокращают:

       node tools/mock-server-pr5.js --port 8080 --origin http://localhost:5555 --ttl 60

2. Клиент на закреплённом порту:

       flutter pub get
       flutter run -d chrome --web-port=5555

Все команды есть и в задачах VS Code (`Terminal → Run Task`, файл `.vscode/tasks.json`).

Параметры при запуске (`--dart-define=ИМЯ=значение`):

| Имя | По умолчанию | Назначение |
|---|---|---|
| `API_BASE_URL` | `http://localhost:8080/api` | адрес сервера |
| `INACTIVITY_SECONDS` | 180 | через сколько секунд без действий выйти |
| `INACTIVITY_WARNING_SECONDS` | 30 | за сколько секунд до выхода предупредить |
| `SESSION_MAX_MINUTES` | 480 | предельная длительность сессии, минут |

## Учётные записи

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin123` | администратор |
| `librarian` | `librarian123` | библиотекарь |
| `reader` | `reader123` | читатель (читательский билет № 1) |

Новая учётная запись из формы регистрации получает роль читателя.

## Что доступно ролям

| Возможность | читатель | библиотекарь | администратор |
|---|---|---|---|
| Каталог, авторы, жанры, издательства (просмотр) | да | да | да |
| Создание, изменение, мягкое удаление | нет | да | да |
| Читатели | нет | да | да |
| Все выдачи, оформление и приём книг | нет | да | да |
| **Мои выдачи** и продление срока | да | нет | нет |
| **Рабочее место** (быстрая выдача и приём) | нет | да | нет |
| Восстановление, удаление навсегда | нет | нет | да |
| **Пользователи и роли** | нет | нет | да |
| **Статистика** | нет | нет | да |

Таблица описана в коде один раз (`lib/auth/permissions.dart`); меню, кнопки и маршруты берут права оттуда. Это только интерфейс: окончательное решение принимает сервер и отвечает 403.

## Как устроена защита

- `lib/router.dart`: функция `guardLocation` вызывается при каждом переходе и при каждой смене состояния входа (`refreshListenable`). Без входа адрес заменяется на `/login?from=…`, после входа пользователь возвращается на запомненный адрес. Если роли адрес недоступен, показывается экран «Доступ запрещён».
- `lib/auth/route_access.dart`: какое право нужно для адреса; проверка адреса возврата (только внутренние адреса, иначе параметр `from` стал бы открытым перенаправлением).
- `lib/core/api_client.dart`: перехватчик добавляет `Authorization: Bearer …` ко всем запросам, кроме `/auth/*`; при 401 токен обновляется один раз, запрос повторяется; параллельные 401 делят одно обновление; неудача обновления даёт чистый выход без повторов.
- Ответ 403 превращается в сообщение «Недостаточно прав для этого действия. …» с названием нужной роли.

## Жизненный цикл токенов

1. Вход: `POST /auth/login` → пара токенов и профиль. В localStorage сохраняются `auth_access_token`, `auth_refresh_token`, `auth_user`, время начала сессии и последнего действия (в браузере ключи имеют префикс `flutter.`).
2. Перезагрузка страницы: сессия восстанавливается из localStorage; если срок бездействия или предел сессии уже вышли, происходит выход.
3. Запрос получил 401: `POST /auth/refresh` с токеном обновления, новая пара токенов сохраняется (роль берётся из ответа сервера), запрос повторяется.
4. Обновление не удалось (токен отклонён): токены стираются, открывается экран входа с пояснением. Если сервер просто недоступен, сессия не сбрасывается.
5. Выход: токены стираются, серверу отправляется `POST /auth/logout`.
6. Бездействие: предупреждение за 30 секунд и выход через 3 минуты; кнопка «Остаться в системе» продлевает сессию. Независимо от активности сессия заканчивается через 8 часов.

## Проверка вручную

- Просроченный токен: сервер с `--ttl 60`, войти, подождать минуту, открыть любой раздел. В сети (DevTools → Network) виден `401`, затем `POST /auth/refresh` и повтор запроса; пользователь ничего не замечает.
- Цикл запросов исключён: запустить сервер с `--ttl 60`, войти, остановить и снова запустить сервер (токены обновления хранятся в его памяти и пропадают), подождать минуту, пока токен доступа истечёт, и открыть любой раздел. В DevTools → Network виден один `401`, один `POST /auth/refresh` с ответом `401`, после чего приложение открывает экран входа и больше ничего не отправляет.
- Предупреждение о бездействии: запуск `--dart-define=INACTIVITY_SECONDS=30 --dart-define=INACTIVITY_WARNING_SECONDS=10` (задача 6).
- Подмена роли (пункт 17): войти как `reader`, в DevTools → Application → Local Storage → `flutter.auth_user` заменить `\"role\":\"reader\"` на `\"role\":\"admin\"` (внутри значения кавычки с обратной косой чертой), перезагрузить страницу. В меню и списках появятся кнопки администратора, но любая операция записи вернёт 403 с сообщением на экране, потому что токен остался читательским.

## Чего нет на лекционном сервере

Для этих возможностей нужен `tools/mock-server-pr5.js`; на лекционном сервере приложение показывает понятное сообщение:

- смена роли пользователя (`PATCH /users/{id}`);
- продление выдачи (`POST /loans/{id}/extend`);
- обязательность токена при чтении, ограничение списка читателей для читателя, проверка спецсимвола в пароле при регистрации.

Статистика собирается на клиенте из обычных списков (параметр `size=1`, нужен только `total`).
